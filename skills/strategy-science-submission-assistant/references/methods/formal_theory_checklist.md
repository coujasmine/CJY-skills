This file is the deep-dive checklist for pure-theory and formal-modeling submissions to Strategy Science. Apply during AUDIT, REVIEW (Reviewer 1: Theory & Contribution), and POLISH Stage 3.

> **Important:** Pure-theory papers (no empirics) ARE accepted at SS — Clough 2026 is the model. But the framework must offer a substantive theoretical movement, and the argument must be rigorous. SS does not accept "we propose a typology" or "we argue for a framework" without sharp execution.

---

## 1. Theoretical positioning

### Lineage anchoring

- [ ] Primary theoretical lineage named in the introduction (see `ss_track_positioning.md`)
- [ ] Anchor citations from that lineage in the first 2 pages
- [ ] Integration of two or more lineages if applicable (Clough integrates Williamson 1991 with Schelling/Farrell-Saloner game theory)
- [ ] Engagement with the latest work in the lineage (Clough cites Jacobides et al. 2024, Baldwin 2024, Schmidt & Foss 2025)

### Theoretical gap or movement

- [ ] What is the theoretical movement? (Mechanism specification / boundary refinement / integration / reconciliation / new construct / new framework)
- [ ] Clough's movement: "I introduce a novel distinction between coordination speed and coordination scope, and use these to reconceptualize governance structures." This is an integration + new construct movement.
- [ ] Movement is articulated explicitly in the introduction
- [ ] Movement is distinct from prior work — not "we extend X to a new context"

## 2. Conceptual building blocks

### Definitions

- [ ] Each key concept defined precisely
- [ ] Definitions distinguish the new concept from related concepts (Clough distinguishes coordination speed from coordination scope; distinguishes opt-in vs. reciprocal vs. consensus-based governance)
- [ ] Definitions are operational enough to enable empirical testing in future work
- [ ] Definitions are stable throughout the paper

### Building block hierarchy

- [ ] Components, primitives, and derived constructs identified
- [ ] Each construct's purpose in the framework explained
- [ ] Cross-references between constructs clear

### Examples

- [ ] Each abstract construct illustrated with real-world examples (Clough uses Windows, iOS, Android, Linux, Symbian, Wikipedia, USB-C, blockchain, Activision Blizzard)
- [ ] Examples chosen to span the conceptual space (not just one or two)
- [ ] Examples disambiguate the concept (e.g., what counts as a hub-and-spoke alliance network?)

## 3. Formal model (if applicable)

### Model specification

- [ ] Players, strategies, payoffs defined
- [ ] Information structure (perfect/imperfect; common knowledge; private signals)
- [ ] Sequence of moves (simultaneous; sequential; cheap-talk rounds)
- [ ] Solution concept (Nash equilibrium; SPE; pBE; correlated equilibrium)

### Assumptions

- [ ] Assumptions stated transparently
- [ ] Assumptions defended substantively (not stipulated)
- [ ] Relaxation of assumptions discussed
- [ ] Robustness to assumption variations addressed

### Analytical results

- [ ] Propositions stated formally (or as identifiable conjectures with logic backing)
- [ ] Proofs in main text or appendix (Clough uses typology arguments and game-theoretic results from prior work rather than original proofs; this is acceptable for SS)
- [ ] Equilibrium uniqueness or multiplicity addressed
- [ ] Comparative statics derived where possible

### Game-theoretic specifics (if applicable)

- [ ] Coordination games / mixed-motive games / cheap-talk / mechanism design — type identified
- [ ] Reference to canonical results (Schelling 1980, Farrell & Saloner 1988, Cooper et al., Van Huyck et al.)
- [ ] Empirical / experimental evidence for the game's predictions cited

## 4. Typology / Framework

### Typology design

- [ ] Dimensions of the typology stated (Clough: governance centralization × platform presence → 2×2 matrix → 4 ideal-type architectures)
- [ ] Each ideal type characterized in detail
- [ ] Examples for each ideal type
- [ ] Boundary cases and blended types discussed (Clough §6.2.1 on blended architectures)

### Trilemma / trade-off / impossibility

- [ ] If the framework includes a trade-off or trilemma, it is stated explicitly
- [ ] The mechanism producing the trade-off is explained
- [ ] Empirical examples confirming or challenging the trade-off cited

### Visual representation

- [ ] Framework summarized in a table or figure (Clough Table 6 + Figure 1 + Figure 3 + Figure 4)
- [ ] Visual is self-contained (readable without reading the text)
- [ ] Visual captures the key claims of the framework

## 5. Theoretical contribution

### Movement specificity

- [ ] One or two specific theoretical movements (not a list of three vague claims)
- [ ] Each movement engages a named lineage
- [ ] Movement is genuinely new (not a re-labeling of existing concepts)
- [ ] Why the movement matters: implications for strategy / for the lineage

### Engagement with prior work

- [ ] Closest prior work named and engaged
- [ ] Differentiation from closest prior work explained
- [ ] What the new framework can explain that prior work cannot

### Testable predictions

- [ ] Predictions stated for future empirical work (Clough §6.2 includes specific predictions about architecture-environment fit)
- [ ] Predictions are falsifiable
- [ ] Operationalization sketched (how would one test the prediction?)

## 6. Boundary conditions and limitations

- [ ] When the framework does NOT apply (Clough's "blended architectures" section)
- [ ] Assumptions that drive the predictions (relaxing them changes the predictions)
- [ ] Scope conditions
- [ ] Acknowledgment of competing frameworks

## 7. Implications

### Theoretical implications

- [ ] How does the framework reshape the conversation in the parent lineage?
- [ ] What new questions does it raise?

### Practical implications (if any)

- [ ] Implications for managers, even in a pure-theory paper
- [ ] Clough provides "simple rules of thumb for ecosystem architects" — this is acceptable practical engagement
- [ ] Implications tied to the framework, not generic

### Future research

- [ ] Specific empirical tests of the framework
- [ ] Methodological extensions (simulation, formal modeling extensions)
- [ ] Boundary-pushing extensions

## 8. Writing style for pure theory

### Voice

- [ ] No empirical verbs ("we find", "our results show") in the main argument
- [ ] Theory-appropriate verbs ("we propose", "the framework predicts", "the analysis yields", "we argue", "the typology identifies")
- [ ] Hedging where appropriate ("to a first approximation", "as a first cut")

### Argument structure

- [ ] Linear argument that the reader can follow
- [ ] Sections labeled with substantive content (not just "Section 2")
- [ ] Sub-sections for each conceptual move

### Citations

- [ ] Heavy citation in early sections (anchoring the lineage)
- [ ] Citations to canonical theoretical references (Williamson, Coase, Schelling, Adner, Jacobides, etc.)
- [ ] Comparison citations explicit ("Unlike X who argues Y, I propose Z")

## 9. Length and structure

### Typical structure (Clough pattern)

```
1. Introduction (intro, theoretical gap, key contributions, roadmap)
2. Coordination Challenges in Innovation Ecosystems (theoretical setup)
3. Governance Structures, Coordination Speed, Coordination Scope (building blocks)
4. From Governance Structures to Ideal-Type Ecosystem Architectures (typology)
5. Discriminating Alignment Framework (the main theoretical claim)
6. Discussion
   6.1. Theoretical placement and implications
   6.2.1. [Specific implication 1]
   6.2.2. Ecosystem Dynamics and Transitions Between Architectures
   6.2.3. Architectures, Capabilities, and Competition
   6.3. Conclusion
```

### Length norms

- Total length: 25-35 pages double-spaced typical
- Tables: 3-8 (typology tables, payoff matrices)
- Figures: 2-5 (framework visualizations, transition diagrams)
- References: 100-200 typical (heavy in the canonical lineages)

## 10. SS-specific concerns

### Pure theory vs. theory paper at adjacent outlets

| If the contribution is... | SS is a good fit? | Better alternates |
|---|---|---|
| New formal model in strategy | ✓ Yes | Management Science (more formal); Org. Sci. |
| New conceptual typology / framework | ✓ Yes (Clough pattern) | AMR (theory-only); Org. Sci. |
| Synthesis of existing theory | ✓ Yes | AMR; Acad. Management Rev. |
| New construct introduction | ✓ Yes | AMR; Org. Sci. |
| Re-labeling of existing concepts | ✗ No | — |
| Pure literature review | ✗ No | Acad. Management Rev.; Annual Review |
| Methodology-only theory | ✗ No | Organizational Research Methods; Management Science |

### What pure-theory papers must NOT do

- Claim empirical findings ("we show empirically...")
- List three vague contributions
- Skip engagement with the latest work in the lineage
- Avoid operationalization sketches (what would future empirical work look like?)
- Avoid acknowledgment of competing frameworks

## Common SS Reviewer 1 concerns (pure theory)

1. **"The contribution is not sharp"** — what specifically is new? Engage closest prior work explicitly.
2. **"The framework is descriptive, not predictive"** — what does it predict beyond what prior work predicts?
3. **"The assumptions are unrealistic"** — defend each assumption substantively or explain why the limitation is acceptable.
4. **"The typology is just a labeling exercise"** — what new explanatory power does the typology provide?
5. **"The integration of [lineage X] and [lineage Y] is forced"** — show how the integration produces new predictions that neither lineage alone could produce.
6. **"Empirical illustration is missing"** — even theory papers benefit from worked examples demonstrating the framework.
7. **"Future research section is generic"** — name specific testable predictions and methodological approaches.

## Calibration anchor

**Clough (2026)**: Single-author pure-theory paper at SS. Integrates Williamson 1991's hybrid governance with the game-theoretic approach to technical coordination (Schelling, Farrell-Saloner). Introduces two new constructs: coordination speed and coordination scope. Identifies an architectural trilemma. Produces a 2×2 typology of four ideal-type ecosystem architectures (firm-controlled platform / shared-governance platform / hub-and-spoke alliance network / symmetric populations ecosystem). 17 endnotes, ~150 references, no proofs (relies on typological logic and prior game-theoretic results). Visual framework summarized in Figure 1, Table 6, and Figure 3.
